02 · 一页结论

先算账，再谈编制

¥1000 万
年媒体预算（示意）
≈¥70 万
2 投手人力中位（30–40 万×2）
≈7%
人力 / 媒体比 · 应盯 CPS 而非 CPL

对东南亚出海消金来说，真正贵的不是人力占比，而是花错的预算： 前端线索好看、授信与放款对不上时，千万级预算会被「假效率」吞掉。

建议目标态（不扩招硬岗）

Agent 负责提案与巡检；人只批关键动作（预算大挪、风险开关、合规争议）。 经营会看 CPS / 授信 / 放款与回传健康度，而不是只看花费与 CPL。

两条组织红线（本简报主轴）

  1. 增长负责人与市场负责人不可合并。目标函数冲突；小团队可「人兼岗」，但 KPI / 汇报线 / 拍板权必须拆开；未来编制禁止再合并。
  2. 投手稳态后优先转岗，不建议一刀裁。演进为「1 投放主责 + 1 AI 运营」，总人头可持平；Agent 替代重复调优，不替代账户监管责任。

产品锚点：CreditAgent 半自动审批队列、护栏与 Kill Switch、预算池、素材合规门禁、转化回传、经营复盘 / 高管周报。不承诺多租户权限体系已上线。

03 · 人效为什么顶墙

两个投手管千万预算，卡在哪

不是「人不努力」，而是三类工作同时抢同一双手：

过载类型 日常症状 只加人会怎样
跨渠道调预算 Google / Meta 来回改日预算，决策慢半拍，高峰期漏批或拍脑袋 第 3 个投手仍在盯盘，吞吐线性涨、沟通成本也涨
合规素材迭代 禁词、APR / 期限披露、疲劳素材替换抢执行时间 仍缺「门禁 + 节奏」，人多不等于合规稳
放款真反馈滞后 平台学的是点击与表单，授信 / 放款回传不健康时越投越偏 报表更多，闭环不闭合，CPS 仍飘

路径 A · 再招投手

编制 +1，成本 +30–40 万/年。决策仍靠人肉盯盘，授权靠口头习惯。

路径 B · 加 Agent 班次

提案与巡检自动化；人审关键卡。授权写进阈值，可回滚。编制优先转岗而非膨胀。

一句话：千万级预算下，优先买的是「决策吞吐 + 后端闭环」，不是再买一双手去点后台。

04 · 协作模型

从「按渠道分账号」到「人审 Agent 提案」

旧习惯：投手 A 管 Google、投手 B 管 Meta，各自优化前端指标。 新习惯：Agent 按 CPS / 风险规则出提案；人按角色审批；增长与市场分列两行，禁止合并成一个总指挥。

模式 人做什么 Agent 做什么
半自动 审待办队列：批准 / 驳回 / 回滚 巡检与提案（预算、素材、风险暂停等）
全自动（护栏内） 盯异常、管 Kill Switch、复盘误伤 阈值内自执行；越界仍进待审
LLM 建议 必须人工拍板 只生成待审建议，不直连执行

05 · 把风险写成参数

可控 ≠ 无人

把「谁能改多少」从口头习惯，改成写进系统的阈值。下面是示意口径，上线前由增长负责人牵头、CEO 签字确认。

参数 示意阈值 谁关心
单次预算变动上限 ≤ 30% 增长 · 投手审批
日累计预算变动 ≤ 50% 增长 · 防止一天内掏空
广告组日预算绝对上限 按账户设定（如 ≤ $20,000） 增长 · 财务对账
低授信自动暂停 近窗授信通过率低于门槛 → 风险优先暂停 增长 · 风控语境

06 · 三条链路

预算 · 素材 · 转化，各改什么

链路 现在 以后（人 × Agent） 谁负责
预算再分配 投手凭感觉挪日预算，缺少冻结与归因 提案 → 资金池冻结 → 人批准 → 分配；可回滚 增长定门槛
投手 / AgentOps 审批
素材合规 上线后才发现禁词 / 缺披露；疲劳素材拖指标 合规门禁 + 疲劳替换节奏；争议素材市场侧拍板 市场定口径

07 · 组织红线

增长 vs 市场：为什么必须分开

未来组织原则：增长负责人与市场负责人不可合并为同一岗位、同一套 KPI。

增长负责人 市场负责人
对什么负责 获客效率与后端结果：CPS、授信、放款、渠道组合、预算再分配门槛 品牌与合规叙事、素材供给、本地化表达与市场节奏
典型问题 「这笔钱换来多少真放款？」 「这话能不能说？素材够不够？品牌有没有伤？」
不该兼什么 不背品牌露出 KPI；不为「花完预算」而投 不直接拍日常调价 / 调预算执行细节
与 Agent 经营目标与授权阈值的主人 合规与素材供给的主人；协作审批，不是同一总指挥

为什么一人兼会出事

  • 目标函数冲突：增长追 CPS，市场追声量与合规表达；兼岗时容易牺牲其中一头。
  • 结果失真：常见两种偏：前端好看、放款难看；或表达过紧、量起不来。
  • 事故难追责：出问题后无法复盘是「策略错」还是「口径错」。
小团队过渡写法

现阶段可以「一个人干两摊活」，但职级称呼、周会汇报线、考核指标必须拆开两套。 规模上来后编制也要拆开，禁止再合并。不要把增长 / 市场压进两个投手编制里「顺便兼了」。

08 · 投手去留

稳态之后：还要不要两个投手？

Agent 稳定后，编制建议从「2 个纯投手」演进为「1 投放主责 + 1 AI 运营」。总人头可持平；不建议双人同时裁掉。

稳态判定（示意，可改）

  • 连续 4–6 周：待审提案按时消化，护栏内少误伤
  • CPS 周报进入经营会，回传健康度能讲清楚
  • 日常从「盯盘改价」为主，变为「批关键卡 + 看异常」为主
出路 做什么
保留 1 名投放主责 账户安全、Kill Switch 值班、异常复盘。千万级预算不宜零人盯账户。
另 1 名转 AI 运营 / AgentOps 训队列规则、整理拒批原因反哺策略、盯转化回传缺口、维护授权阈值与周报口径。
不建议 Agent 一稳就裁掉两人；或把增长 / 市场负责人塞进这两个编制兼掉。

技能迁徙（对照日常）

读决策卡理由链改护栏 / 授权阈值
调预算审预算池提案与回滚
上素材过合规门禁 + 疲劳替换节奏

09 · 90 天与拍板

怎么走，CEO 要拍哪几下

阶段 动作 验收
D0–30 半自动上线；写入护栏与 Kill Switch 值班人；增长 / 市场分岗书面确认（可兼人、不兼糊权责） 队列日清；无越权直执
D30–60 CPS 周报进经营会；回传健康度固定议程；整理拒批原因 会上看后端指标，不只看花费
D60–90 评估护栏内部分自动执行；启动「1 投放主责 + 1 AI 运营」转岗（示意 Q2/Q3） 稳态标准达标；转岗表签字

CEO 拍板清单（5 件）

  1. 目标 CPS（及不可接受的授信/放款底线）
  2. 授权阈值表（单次 / 日累计 / 绝对上限）
  3. Kill Switch 值班人（主 + 备）
  4. 书面确认：增长负责人与市场负责人分岗（KPI 与汇报线拆开）
  5. 投手转岗时间表（示意：稳态后 1 人转 AI 运营，不双裁）
收束

人少不是弱点，权责糊才是。Agent 用来抬吞吐；分岗用来保目标不打架；转岗用来留住懂账户的人。 这三件事对齐了，¥1000 万预算才值得继续加码。
