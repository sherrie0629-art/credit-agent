# 归因升级：从「结果记账」到「前瞻归因」

## 现状（已确认）

`分渠道后端归因` 卡片目前只展示某个周期的静态结果：渠道 / 广告组、放款金额、花费、线索与放款笔数、CPS、授信通过率，外加一条素材下钻。数据来自 `channelBreakdown`（周期聚合），洞察层 `decisionBrief` / `opsDiagnostics` 已有规则文本，但归因本身回答的仍然是「上周发生了什么」，没有回答「为什么」「接下来会怎样」「该动哪一刀」。

## 真正的归因应该输出四层内容

1. **贡献层（Who）** — 谁带来了放款：渠道 / 广告组 / 素材 / 关键词与人群维度的放款额与占比，以及相对上期的增量分解（增量来自量还是效率）。
2. **因果层（Why）** — CPS 变化的杜邦式拆解：CPS = 花费/放款 = CPC × (1/CVR线索) × (1/授信通过率)。把本期 CPS 的偏差按「流量成本 / 线索转化 / 风控通过」三段做贡献度归因，明确指出这次超标主要由哪一段引起、贡献了多少美元。
3. **时滞层（When）** — 消费信贷的放款有 T+N 的滞后。用 `leads.click_at` → `lead_events.occurred_at` 计算转化时滞曲线，对本期未成熟的线索做成熟度折算，给出「已实现 CPS」与「时滞校正后的预测 CPS」，避免把新广告组误判为差。
4. **前瞻层（What next）** — 基于趋势与置信度的预测与处方：
   - 预测放款与预测 CPS（未来 7 天，含区间）；
   - 素材疲劳与广告组衰减的早期信号（CTR/频次斜率、CPS 斜率）；
   - 每个广告组一句「处方 + 预计影响」，例如「Search-品牌 预计 3 天后 CPS 破 $22，建议降预算 15%，预计节省 $1.2k / 少 2 笔放款」；
   - 样本量与置信标注，样本不足时明确写「数据不足，勿动」。

## 实施方案

### 阶段一：因果拆解与增量归因（核心）
- 在 `src/lib/creditagent/report.ts` 新增纯函数 `decomposeCps(period, prior)`：输出每个广告组三段（CPC / 线索转化率 / 授信通过率）对 CPS 变动的美元贡献，加总等于总变动。
- 新增 `decomposeGrowth()`：放款额同比变化拆成「量效应 × 效率效应 × 结构效应」。
- 卡片内新增一条紧凑的贡献条（三段色块 + 主因文案），点击展开明细。

### 阶段二：时滞校正与成熟度
- 从 `leads` + `lead_events` 统计历史「点击→放款」时滞分布，得到成熟度曲线。
- 归因卡展示：已实现 CPS / 校正后 CPS / 该周期线索成熟度百分比。

### 阶段三：前瞻预测与处方
- 基于 `creative_metrics` / 周期事实做简单稳健回归（近 14 天斜率 + 置信区间），预测 7 天 CPS 与放款。
- 每个广告组生成一条处方，复用现有 guardrail 上限（预算变动幅度受 `agent_settings` 约束），并可一键跳转到审批流。

### 阶段四：UI 重构
- `分渠道后端归因` 卡改为：顶部结果数字 → 中部因果贡献条 → 底部前瞻预测与处方，一屏内三层可读。
- 保留现有素材下钻与深链能力。

## 技术要点
- 全部拆解与预测走确定性 TS 计算，不交给大模型，保持与现有双轨防幻觉策略一致；LLM 只负责把结构化结论改写成人话。
- 新增字段通过 `fetchOpsAnalyticsFn` 返回，`report.ts` 内保持纯函数便于单测。
- 时滞与斜率查询下沉到 SQL 视图，避免前端多次往返。

## 建议实施顺序
先做阶段一（因果拆解），它信息增量最大且不依赖新表；确认效果后再推进阶段二、三。
